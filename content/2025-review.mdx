# 2025 Year in Review

## January and February

This year started with me feeling more confident in my React skills after doing a few smaller projects. I was ready to challenge myself with a more complex project in React. After reading the amazing fiction book Tomorrow and Tomorrow and Tomorrow by Gabrielle Zevin, I was feeling inspired to build a game I had been thinking about for a few months. So I started building my math game Frectangles.

I was addicting to building this for almost two straight months. I even visited my best friend in DC who I hadn't seen in over a year and half the time I was sitting on her couch working on my game. I've never been a huge video gamer but building this game was full of so many fun challenges. I really deepened my understanding of React so much and learned a lot about UX best practices too. I used Hotjar to analyze session replays and created a bunch of events that get sent to Hotjar when someone completes a level, undoes an action, etc. I'm really interested in being a Product Minded Engineer so I've focused a lot of time employing practices that allow me to get to know how my users are using my apps, any challenges or frustrations they have, etc. Hotjar has been insanely helpful for this, I cannot reccomend it enough.

Also during this time I participated in a month long Hackathon, although I was more focused on my game so the Hackathon didn't get as much love. One thing I learned is that I really needed to get better at using Git and Github to collaborate. This Hackathon was my first experience using Github collaboratively and I was very confused with pulling, fetching, and handling merge conflicts, and struggled with writing good commit messages and PR descriptions.

## March

After applying to some jobs I decided I needed to add backend and Tailwind to my skillset since there were so many jobs expecting those things. So I paused my work on my game and pivoted to working on a Frontend Mentor Todo list app with an Express backend. I have CORS errors I've still never figured out but it was still a good learning experience.

## April, May, and June

In April I started an Apprenticeship at Gridiron Surivivor where I was working with a team on a Secret Santa app. I learned a ton about writing unit, integration and end to end tests, using ESLint and Prettier, and writing good PR descriptions. This was the perfect opportunity to see how a professional software development lifecycle worked with tickets, sprints, a kanban board, release cycles, retrospectives and a CI/CD pipeline. It really inspired me to apply a lot of the same practices to my personal projects to be more organized and keep myself on track. The LGT community is also so so great to have all these mentors and people building cool things to look up to.

## July and August

Things had slowed down for Gridiron Survivor and I had a renewed energy to continue working on my game. Having experienced the joy of creating and closing tickets for Gridiron Surivor, I creating a bunch of tickets for my game and it gave me so much motivation to keep working so I could close them one by one. I was also on my first podcast, John Crickett's Coding Chats talking about the game and I really felt like finishing it and getting users would be my ticket to getting a job.

## September, October, November and December

In September I got to go to the Commit Your Code conference and meet all of my LGT friends in person. And in October I went to see my best friend speak at Vite Conf in Amsterdam. Both were amazing experiences that I will cherish!

Through being on podcast, I got an offer to do a paid internship at a small startup called Meet Near Me. This involved learning Golang, Alpine JS, Templ, and HTMX and was much more complicated than any project I've done up to this point. I learned Go with an amazing resource called Learn Go with Tests which takes you through Test Driven Development as a way to learn Go. This startup had a very complex build system that taught me so much about all the things that need to happen to get files to format, compile, build into a binary and provide the hot reloading experience I had taken for granted. I had the opportunity to work on several user-facing features where I had to practice empathizing with our customers and considering tradeoffs of various approaches to the UI. As I grew to understand the product and company direction more, I even started finding communities of potential users to learn about their wants and pain points. This culminated in building an embeddable widget that shows local events with search and filtering for newletter publishers to include in their websites. This was very complex for me and I had to rely on AI a lot to make it happen. I learned so much in the process of building, debugging, and refactoring it. As my internship has been winding down, I've also been learning about best practices in Next JS and working on this Portfolio and Blog (in Next).

## Looking Forward

Towards the end of December, I got a full time job offer as a Frontend React Developer at an edtech startup (my dream scenario) that starts in January. This was after 18 months of learning and about 120 job applications. I'm really excited to be working with a tech stack and industry I feel more familiar with and to get health insurance(!!). I'll be rebuilding the frontend one of their existing apps from scratch in React.

## Goals for 2026

I want to continue getting even more comfortable with git and start using interactive stashing or committing and squashing more fluently to make my commits modular to the point where my commit history is decent documentation. I've started reading this book _Ultimate Git and Github for Modern Software Development_, and it described your local branch as a playground. I want to get to the point where I can use my local branch as a playground instead of just using it the exact same way I use my remote branch. Currently, especially when I'm using AI to build a large feature or to fix something, I often have a lot of code changes that aren't even staged so my playground is just my working directory. I don't commit changes until I know they work within the whole and sometimes that makes my commits huge or messy and confusing. And I end with so many changes that I'm not even sure if they are all necessary. I think worktrees may also be helpful for dealing with this but I don't know much about them yet.

As a teacher, I often had my students do math on whiteboards to lower the pressure of "committing" something to an actual piece of paper. This was so helpful for getting more rough ideas and experiments out in the open. I want to feel that same low barrier to entry when I'm coding. I want to make a bunch of changes and then temporarily undo one of them and redo it easily without copy and pasting stuff to my clipboard 😅. I want to be able to commit or chunk and name changes more fluidly so I can reason about things more easily. I don't fully know what I want or what's possible but I'm looking forward to reading more of this book to learn.

Since I'll be building a web app mostly by myself at my new job, I also want to learn more about design patterns, github actions, using Claude Code, accessibility, and gain a deeper understanding of React. I want to finish the half-started blogs I have on here and to keep blogging when I encounter new and interesting problems. I think having these challenges documented will be super helpful for applying to jobs in the future and when I run into the same problems again and forget how I solved them. Hopefully they're also helpful for anyone else encountering these kind of things.
